# 📜 1. Custom Instructions Exercises

In these exercises, you will:
- Read project-wide and path-scoped custom instructions
- Understand how instructions scope to different files
- Create a new path-scoped instructions file
- Validate that Copilot respects your custom rules

## 🔍 Exercise 1.1: Examine the existing custom instructions

Get familiar with how this repo layers project-wide and path-scoped instructions before writing your own.

1. Open the project-wide instructions file at [.github/copilot-instructions.md](.github/copilot-instructions.md) and read through it. Note that it has **no YAML frontmatter** and applies to every Copilot request in this workspace.
1. Open the [.github/instructions/](.github/instructions/) folder and review both files:
    - [.github/instructions/backend.instructions.md](.github/instructions/backend.instructions.md)
    - [.github/instructions/frontend.instructions.md](.github/instructions/frontend.instructions.md)
1. Compare their YAML frontmatter. What do you notice? Look for:
    - The `applyTo` glob pattern that scopes each file to a subset of the workspace.
    - The optional `description` field on the frontend file and what role it plays.

## 🧪 Exercise 1.2: Scaffold a new path-scoped instructions file

Create a new instructions file that only applies to backend Vitest specs, then verify Copilot honors a rule you add to it.

1. Run the `/create-instructions` slash command in the Copilot chat with the following prompt:
    ```text
    /create-instructions a new path-scoped instructions file targetting backend test case files. It must:
      - apply only to files matching backend/**/*.test.ts via the `applyTo` frontmatter field
      - capture the Vitest + supertest conventions used in backend/test/
      - require that new tests follow the patterns in .github/instructions/backend.instructions.md
    ```
1. Open the generated file and review its contents. Confirm the YAML frontmatter contains `applyTo: "backend/**/*.test.ts"`.

## ✨ Exercise 1.3: Modify and validate the new instructions file
1. Add a rule to the new instructions file that requires Copilot to mark every test case it generates with a `Generated by GitHub Copilot` comment:
    ```text
    ## Documenting unit tests
    Add "Generated By GitHub Copilot" comment at the top of the file if the test was generated by Copilot. This helps set expectations for maintainers about the test's origin and may inform future decisions about whether to refactor or rewrite it.
    ```
1. Open [backend/src/routes/skills.ts](backend/src/routes/skills.ts) and ask Copilot to generate unit tests for it. 
1. Inspect the generated test file. **Was the new instruction respected?** The file should begin with `// Generated by GitHub Copilot` comment. If not, refine the wording of the rule and try again.
